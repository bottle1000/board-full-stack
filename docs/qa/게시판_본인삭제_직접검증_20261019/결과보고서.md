# A07 게시글 삭제·논리 삭제·조회 404 직접 검증

사용자가 실행일 2026-10-19, postId 100013을 명시했고 원본 3장을 제출했습니다. 지원자가 실행·캡처했고 AI는 제출 자료를 대조했습니다.

| 단계 | 기대 | 실제 | 증거 |
|---|---|---|---|
| 테스트 글 삭제 | 200, success=true | 200, success=true, data=null, error=null | API14_삭제200.png |
| 같은 글 DB 조회 | 행 유지, is_deleted=1 | 1행, 작성자10316·원본 제목·내용 유지, is_deleted=1 | DB01_삭제후_상태1.png |
| 삭제된 글 조회 | 404, POST_NOT_FOUND | 404, success=false, POST_NOT_FOUND, data=null | API15_삭제후조회404.png |

삭제 전 자료는 [앞선 A06의 마지막 SQL](../게시판_타인권한_직접검증_20261019/DB03_삭제시도후.png)입니다. 동일 post_id=100013, author_id=10316, 제목 QA-A06 원본 제목, 내용 QA-A06 원본 내용을 비교했으며 삭제 상태만 0에서 1로 변경되었습니다. DB 행이 물리적으로 사라지는 대신 삭제 표시를 유지하고, 서비스 조회에서는 제외되는 동작을 확인했습니다.

삭제 응답 timestamp는 2026-10-19T16:59:06.864518, 조회 응답은 2026-10-19T17:00:22.319113입니다. 타임존 오프셋이 없어 변환하지 않았습니다. SQL 조회 시각은 미확인입니다.

삭제 요청 화면의 이름은 ‘API14 A 본인 글 삭제’입니다. 토큰 값·인증 주체는 캡처로 독립 확인하지 않았습니다. 현재 구현의 작성자 검사와 요청명은 보조 맥락이며, 캡처가 직접 입증하는 것은 동일 글의 삭제 성공·DB 변경·삭제 후 조회 차단입니다. baseUrl 실제 주소와 실행 소스 버전은 미확인입니다.

조회 요청 이름은 ‘API02 게시글 단건 조회’이지만 이번 사전조건은 삭제된 글이므로 API15에 해당하는 실행으로 분류합니다. 요청 이름만으로 잘못된 테스트라고 판정하지 않습니다. Postman 자동 검사 실행·통과 여부는 화면에 없으므로 주장하지 않습니다.

## 포트폴리오 반영 문장

게시글 삭제의 HTTP 200 확인 후 동일 ID를 SQL로 조회해 is_deleted가 0에서 1로 변경되고 원본 데이터가 유지되는지 확인했습니다. 이어 같은 글을 조회해 404·POST_NOT_FOUND를 확인하고 논리 삭제와 서비스 조회 결과를 연결했습니다.
